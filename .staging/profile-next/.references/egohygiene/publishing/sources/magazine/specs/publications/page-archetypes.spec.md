Purpose

This specification defines the recurring page archetypes used throughout Ego Hygiene publications.

Page archetypes are reusable structural patterns.

They are NOT:

individual pages

They ARE:

repeatable page families

Individual pages inherit from archetypes.

---

Core Philosophy

A publication should not be built from isolated pages.

A publication should be built from reusable page systems.

The relationship is:

archetype
→
template
→
page

Example:

Pillar Front Page
→
Movement Template
→
Movement Page

Archetype Definition

An archetype defines:

purpose
content structure
visual hierarchy
recurring regions
required components

An archetype does NOT define:

specific content
specific atmosphere
specific illustrations

Those are provided later.

Archetype Evolution

Archetypes should emerge from reference analysis.

Do not create archetypes speculatively.

New archetypes should only be added when:

multiple pages share the same structure

The publication should remain evidence-driven.

---

Archetype Extraction Process

Reference Page
→
Structural Analysis
→
Archetype Identification
→
Archetype Refinement
→
Template Creation

---

Validation

When evaluating a page ask:

What archetype does this belong to?

before asking:

What components does it contain?

Archetypes are higher-level structures than components.

---

Long-Term Goal

The publication should eventually consist of a small set of reusable archetypes.

Example:

10 archetypes
→
hundreds of pages

This reduces design duplication while preserving visual consistency.

---

Guiding Principle

Pages are instances.

Archetypes are systems.

Design the system first.
