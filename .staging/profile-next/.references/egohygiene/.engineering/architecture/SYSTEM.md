# 🧠 SYSTEM — AI-Native Engineering System

---

## 🎯 Purpose

This document defines the universal engineering system used to design, build, refine, and evolve software projects.

The purpose of this system is to:

- reduce cognitive load
- externalize architectural thinking
- maximize development velocity
- maintain high quality standards
- create reproducible engineering workflows
- enable effective human-AI collaboration

This system treats repositories as living knowledge systems rather than code containers.

---

# 🧠 Core Philosophy

Software is not built from code.

Software is built from:

    Understanding
    ↓
    Structure
    ↓
    Specification
    ↓
    Implementation

Code is the final artifact.

The primary responsibility of the human is:

    Define

The primary responsibility of AI is:

    Implement

---

# 🧭 Core Principles

## Architecture First

Design before implementation.

The system should be understood before it is built.

---

## Specification Driven Development

Specifications define intent.

Implementation follows specifications.

Specifications should outlive implementation.

---

## AI as Force Multiplier

AI is not a replacement for engineering.

AI amplifies engineering.

The goal is:

    Better decisions
    Faster implementation

---

## Audit Driven Refinement

Every system accumulates drift.

Regular audits ensure:

- consistency
- maintainability
- correctness
- simplicity

---

## Externalized Cognition

Repositories should store:

- decisions
- architecture
- standards
- patterns
- rationale

Do not rely on memory.

---

## Composability

Systems should be built from:

- modules
- capabilities
- interfaces

Avoid tightly coupled designs.

---

# 🏗️ Repository Philosophy

Repositories are:

    Knowledge Systems

not:

    Collections of Code

Code should be the final layer.

# 🧩 Specification System

Specifications define:

    How Things Should Be Built

Specifications are reusable.

Examples:

- flutter-engineer.spec.md
- architecture.spec.md
- issue.spec.md

Specifications should remain:

- technology focused
- implementation agnostic
- reusable

---

# 🤖 Agent System

Agents define:

    How AI Thinks

Examples:

- flutter-engineer.agent.md
- reviewer.agent.md
- auditor.agent.md

Agents consume:

- specifications
- repository context
- tasks

Agents do not define architecture.

Agents execute architecture.

---

# 🛠️ Skill System

Skills define:

    How AI Performs Specific Work

Examples:

- state-management.md
- localization.md
- testing.md
- notifications.md

Skills are:

- reusable
- focused
- domain specific

# 🧾 Issue Philosophy

Issues should be:

- atomic
- scoped
- executable
- testable

Large ideas should be decomposed.

Complexity should be reduced before implementation.

---

# 🌿 Branch Philosophy

Every task receives a branch.

Examples:

    feat/<feature>
    fix/<bug>
    chore/<task>
    refactor/<area>

---

# 🧪 Testing Philosophy

Testing occurs at multiple layers:

- component
- feature
- milestone

Milestones represent validation points.

Not every issue requires exhaustive testing.

---

# 🔍 Audit Philosophy

Audits are mandatory.

Audits evaluate:

- architecture
- implementation
- DX
- UX
- maintainability
- simplification opportunities

Audits generate:

- findings
- recommendations
- new issues
